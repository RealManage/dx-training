Prompts for Claude Code (Datadog MCP)

P1List the services that have continuous profiling data in the last hour.
P2Which prod endpoints in service have the worst p95 over the last 24 hours? Use the trace metrics, not span counts, and give me a link.
P3For the trace below, from prod service, in three short bullets: how long did the request take, how much was SQL, how much was our own code? Then paste the trace link.
P4For the trace below, from prod service, use the profiler to find our slowest method, then read that code: what does it do, why is it slow, how could we make it faster? Then paste the trace link.
P5Is endpoint slow because of our C# or the database? Check traces and the profiler; tell me which queries you ran.
P6We got a latency alert on prod service around time UTC. Real regression or noise? Compare against the same time the day before.
P7Which exact queries, metrics and time windows did you use? Give me Datadog links.
P8Draft a Jira ticket (do not create it) for endpoint: summary, trace and profiler evidence with links, next step.
P9Find the most recent Exception Replay snapshot for exception type in prod service and explain what the captured variables tell us about why it failed.
P10Dev only. Start a Live Debugger session on service in dev and add a logpoint just before line N of file, logging variables, only when condition. Don't pin a version. Then: show me what it captured, then disable it.

Click paths

K1APM → Traces: service:… resource_name:"…" env:prod @duration:>8s. Older than 15 min = indexed spans only.
K2Open a trace: Flame Graph · Waterfall (expand all) · Span List (group by Service, read Exec Time).
K3Click a span → tabs: Overview · Infrastructure · Metrics · Logs · SQL Queries · Profiles.
K4APM → Service: check operation, env, version first.
K5APM → Profiles → Explorer: Wall Time → endpoint on the right → Filter flame graph → method:"Class.Method()" → focus_on.
K6Errors → Error Tracking → issue → Stack Trace: look for Exception Replay snapshot. Find issues with one: Logs (Flex) source:dd_debugger @debugger.product:er.
K7APM → Debugger → New Session → Start debugging manually → service, env → file → click the gutter → template, when → Start Debug Session.

Check Claude's work

  1. C1 Ask which query it ran, and for a link.
  2. C2 Open the link; check service, env, time range, profile type, one number.
  3. C3 Distrust "0 results" and rates from span counts.
  4. C4 Compare with the same time yesterday before calling it a regression.
  5. C5 Tell it what Datadog can't see: recycles, config changes, manual work.

Gotchas

  • G1 Profiles opens on CPU Time; use Wall Time for requests that wait.
  • G2 Wall Time counts idle threads; filter to an endpoint and our code.
  • G3 The Method list ranks self time; to find a caller, use Filter flame graph.
  • G4 Async work shows under the awaited call; read down to our widest frame.
  • G5 Frames show line 0 until DX-1570.
  • G6 No profiles before 2026-09-22.
  • G7 Thin or empty profile? Widen the time range.
  • G8 Span counts are sampled; use trace.* metrics for rates and percentiles.
  • G9 "0 results" may be a silently ignored filter; group instead, or check the UI.
  • G10 Check the operation and env selectors before comparing numbers.
  • G11 The MCP URL needs ?toolsets=all; restart Claude Code after changing it.
  • G12 Claude only sees what Datadog records; tell it what changed.
  • G13 Exception Replay starts on the 2nd occurrence; max 1 per type, server, hour.
  • G14 Some exceptions never get a snapshot ("internal error").
  • G15 Live Debugger needs a setting on the service: management-api dev only for now.
  • G16 Strict redaction (most prod services) blocks logpoints.
  • G17 Logpoints on await lines never fire.
  • G18 Watch the session page; Logs lag about 3 min.
  • G19 Leave Target specific instances empty while testing.
  • G20 Logpoint create "failed"? List the session before retrying.
